## Scaled content abuse — operational consequence for Radius OS

**Source:** [Google Search spam policies — Scaled content abuse](https://developers.google.com/search/docs/essentials/spam-policies)

Google defines scaled content abuse as generating many pages primarily to manipulate
search rankings rather than help users — **no matter how it is created** (A5 in the
shared evidence base).

**March 2024 clarification:** method-agnostic (automation, humans, or both).

**August 2025 spam update:** reinforce purpose-testing; one-page-per-run remains the
hard gate in this skill.

**Operational rules:**
1. One page per `create-content` invocation
2. Refuse empty / generic differentiation
3. Named human must review before publish
4. Do not mass-fill a content calendar unattended
5. Content translation is out of scope (automated translation at scale is a named
   scaled-abuse example)

## AI-assisted drafts (A4)

Appropriate use of AI is not against Google's guidelines. Purpose is tested via
Who/How/Why. Disclose AI assistance when a reader would reasonably ask how the page
was made. Never invent first-hand experience — use `[AUTHOR INPUT REQUIRED]` /
`[VERIFY]` only for specific unknowable facts.

## Word count / density

Length follows coverage from the brief. No padding. Keyword **placement**, never
frequency (A1, A7).
